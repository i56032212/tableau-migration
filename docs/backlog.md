## 二、開啟 Tableau 檔時還不支援的寫法

解析時列入 `unsupported`，報表進人工佇列（完整的清單在 README「已知限制與待驗證」最後的「尚未支援」）：

- `SCRIPT_*`、`MODEL_*` 的 gp、rl 與有序的預測變數；`RAWSQL_*` 在萃取與檔案上（與 `RAWSQL_SPATIAL`）
- LOD 的維度中的 INCLUDE／EXCLUDE；Relationship 模型中含 LOD、又要以半連接套用的篩選
- Data Blending：同一個彙總混用兩個資料源的欄位、同一個 LOD 混用兩個資料源的欄位、次要資料源的內容篩選
- 預測指定的彙總依據中平台不照做的組合（比檢視粗、月→週、日→時、年份的日期部分、SUM／COUNT 以外的彙總）、預測改用
  較細細度時文件沒有寫明的情況、只以維度分群的叢集、標題中產生的緯度經度
- 故事點加上的 Measure Names／Values 與新的 Table Calculation 欄位、篩選的其他變更（edited 等）
- 多個維度的集合以成員顯示、不同維度的集合組合成的合併集合
- 尚未併入 .tdsx 的 Published Data Source、舊版的 .tde 萃取
- 要求檢視者輸入自己的資料庫帳號或以檢視者身分模擬的連線（要改用列層級權限重寫）

另有一類**不會**列入 `unsupported`：編輯器裡可以設定，但 .twb 中的寫法沒有樣本、解析器不認得——次要計算、堆疊標記的
開關（2026-11-23 在約 300 份公開報表與 GitHub 上找過）。表計算的自訂排序、篩選控制項的自訂、顯示歷程、Story 的格式、
分頁顏色與動畫已經從 .twb 解析（2026-11-23）

- **剩下的功能做哪些**：建議等盤點結果，依公司報表實際用到的排序，而不是照 Tableau 的功能表一項一項做
- **試點的報表**：盤點後挑選
- **離線安裝檔中專有授權的驅動**：伺服器版與桌面版的安裝檔帶著所有資料庫驅動，其中 SAP HANA（hdbcli，SAP Developer
  License Agreement）、Teradata（teradatasql，Teradata License Agreement）與 Db2 的 clidriver（IBM 的授權）是專有授權。
  公司沒有用到的可以不帶；用到的要確認授權條款允許這樣散布。**repo 是公開的**，`offline-v0.1.0-20261125` 的 Release
  誰都下載得到（2026-11-25 告知使用者後，使用者決定照樣發布）
- **標題中的量值**：Tableau 知識庫 001458099（Adding Totals to a Title）寫的是標題中的欄位值在檢視中有多個不同的值時
  顯示「範圍」；本平台把標題中的量值當作全部資料的合計（依公開報表推定）。欄列架上有離散維度、量值在各標記不同時
  兩者不同。要在公司的 Tableau 上試一張工作表確認：確認是「範圍」時改成與 Tableau 相同（目前顯示合計的標題會改變）

## 五、建議的順序

1. 在 Windows 上補上引擎再跑一次一鍵檢查：裝 PostgreSQL（Spark 另需 Java 17 與 `uv sync --group spark`）後設
   `TMIG_REQUIRE_ENGINES=1`。沒有引擎的部分 2026-11-16 已經跑過（第三部分的 5）；公司的電腦若不是那一台，
   也在公司的電腦上跑一次
2. 盤點 Tableau Server（第三部分的 3），挑試點的報表
3. 設定公司資料庫的連線並實測（第三部分的 1、2）
4. 移轉試點的報表、比對數字，把不一致的地方修掉
5. 試用桌面版的安裝檔（2026-11-21 已在 Windows 本機重建）：安裝、開啟報表、編輯、存檔、登入伺服器與發布；
   伺服器版的離線安裝檔裝在測試用的 Windows Server 上（第三部分的 11），桌面版連上去發布
6. 依盤點中實際用到的功能補第一、二部分
