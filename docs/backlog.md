## 二、開啟 Tableau 檔時還不支援的寫法

解析時列入 `unsupported`，報表進人工佇列（完整的清單在 README「已知限制與待驗證」最後的「尚未支援」）：

- `SCRIPT_*`、`MODEL_*`、`RAWSQL_*`
- LOD 的維度本身含 LOD；Relationship 模型中同一個彙總用到多張資料表的欄位
- Data Blending：同一個彙總混用兩個資料源的欄位、LOD 中次要資料源的欄位、次要資料源的條件與 Top N 篩選
- 預測的其他結果類型（趨勢、精確度等）、取消彙總的叢集、標題中的 Table Calculation 值
- 故事點記下的其他狀態（排序、欄列架的變更、註解）
- 合併集合的 XML 寫法（公開報表中還沒看到）、尚未併入 .tdsx 的 Published Data Source、舊版的 .tde 萃取
- 要求檢視者輸入自己的資料庫帳號或以檢視者身分模擬的連線（要改用列層級權限重寫）

另有一類**不會**列入 `unsupported`：編輯器裡可以設定，但 .twb 中的寫法沒有樣本、解析器不認得，從 Tableau 開啟的
報表會是預設值——次要計算與表計算的自訂排序順序、堆疊標記的開關、篩選控制項的自訂（顯示「全部」、搜尋、
套用按鈕等）、頁面的顯示歷程、Story 的格式、分頁顏色。盤點時要留意報表有沒有用到；拿到樣本就能補上解析

## 三、還沒驗證的

這些比第一部分重要：目標是數字可以驗證與 Tableau 相同，而下面每一項都還沒有在公司的環境證實。

1. **資料庫實機**：實跑過的只有 PostgreSQL、MySQL、Spark 與 Trino（Trino 靠 CI 的 Docker，最近沒有跑）。Oracle、SQL Server、
   Snowflake、Redshift、BigQuery、Teradata、Hive、Impala、Db2、SAP HANA 都是轉回 DuckDB 模擬。公司用到的資料庫要
   實測：方言轉譯的 SQL、連線設定、Initial SQL
2. **公司環境**：Live 連線的設定檔（`tmig connections template`、`tmig connections check`）、登入（OIDC 或反向代理）、
   權限與排程的匯入都還沒在公司環境跑過
3. **Tableau Server 盤點**：由使用者以自己的 PAT 執行 `tools/tableau_server`（見 `tools/README.md`），再以
   `tmig census`、`tmig inventory` 看哪些報表符合起步條件、用到哪些還沒做的功能
4. **試點**：還沒有拿 1–2 份真實報表從頭到尾移轉並以 `tmig verify` 比對數字
5. **Windows**：2026-11-16 第一次在 Windows 11 上跑一鍵檢查（ruff、pyright、完整的 pytest）、`regen_ir.py`、
   `check_commit.py` 與前端的建置，修掉當時發現的四個問題（存檔時檔案正被讀取而換不上、兩個只差大小寫的前端
   檔名讓建置失敗、一項端到端測試依賴 Linux 字型的行高、示範報表的匯入紀錄過期）。前端在 Windows 上建置的結果
   與 Linux 上提交的 web/dist 相同。還沒驗證的：
   - 需要引擎的測試 110 項（PostgreSQL 63、Spark 37、MySQL 10）：那台電腦沒有引擎，略過了。MySQL 的臨時伺服器在
     Windows 上不啟動（`kernel/tests/engines.py`），要以 `TMIG_TEST_MYSQL` 指向現成的伺服器
   - 桌面版：2026-11-21 在 Windows 本機重建安裝檔（含新的工作區排列、單一功能表列；做法見 `desktop/README.md`）。
     打包的引擎通過冒煙測試；建好的外殼啟動後開出視窗、引擎只在本機聽候、沒帶權杖的請求被拒絕、關閉外殼後引擎
     跟著結束。2026-11-21 在真正的視窗中驗證過（以 WebView2 的除錯埠操作視窗裡的頁面，原生選單以 Win32 API
     讀出）：沒有原生選單、功能表列只有一排，開啟報表後的編輯器版面、開功能表、把欄位拖到色彩、新增 dashboard
     並拖入兩張工作表都正常，「關於」指令可用。還沒驗證的：實際執行安裝檔（安裝與解除安裝）、原生的選檔與
     存檔對話框（除錯埠操作不到，驗證時是直接請本機引擎開啟報表）、「結束」、登入伺服器與發布、沒有 WebView2 的電腦
6. **Snow Sports Rental Operations Overview 報表**：42 張工作表、2 個 dashboard 都能解析、查詢與呈現，沒有不支援的元素。2026-11-19 使用者提供了 Overview 的 Tableau 截圖，已依它修正版面與格式（見 README「依 Tableau 的畫面修正」），以 11 月 18 日為基準日時畫面上的數字與截圖相同。
   還沒做的：下拉式控制項的外觀等幾處小差異；Resort View 沒有截圖可以對照；只比了 Overview 畫面上看得到的數字，還沒有用 `cases.yaml` 與 Tableau 匯出的 CSV 做完整的計算比對；依地區設定的寫法只有繁體中文的日期與年份；自然排序在 Live 連線上還沒有與 Tableau 實機比對。前端的修改中，分面儲存格相連（甜甜圈的大小）與依瀏覽器語言的日期寫法沒有端到端測試，只在這份報表的畫面上看過
7. **與 Tableau 的畫面比對**：README「已知限制與待驗證」中標為「推定」的行為（版面、格式、預設值、圖片形狀的
   大小與著色等）還沒與 Tableau 的畫面對過；`tools/compare_screens` 可以用來比對

**程式錯誤（先修）**

桌面版編輯器與核心的 9 項已處理（2026-11-21，工作目錄中，尚未提交；完整的測試還沒跑）：

- ✅ 已修：桌面版匯出 CSV 與 Excel 交叉資料表一定失敗——本機引擎的匯出原本只接受 .png、.pptx、.pdf，補上
  .csv、.xlsx。稽核寫「沒有訊息」不正確：錯誤一直都顯示在對話框裡（稽核的腳本只看右下角的訊息）；訊息
  改成「無法下載：原因」、不帶 HTTP 狀態碼
- ✅ 已修：Measure Values 拖到標籤時各量值疊在同一格——編輯器自動加上 Measure Names（位置部分是推定的，見
  README「已知限制與待驗證」）；之後把 Measure Names 拿掉，畫圖時各量值仍然分開排列。查的時候另外發現並修掉：
  兩層以上的列標題加上欄維度的文字表（例如列是類別、Measure Names，欄是地區），每一欄被壓成 20 像素、數字
  左右疊在一起——標題區域分隔線的圖層用了連續的 x，Vega-Lite 因此丟掉欄寬的設定（與 Measure Values 無關，
  兩個一般的維度在列架上也一樣）
- ✅ 已修：雙軸加趨勢線整張圖查詢失敗（`Duplicate data set name: "__ref_trend_pathgroup"`）——兩條趨勢線的
  圖層同名；改名之後另外發現以 Measure Names 上色時趨勢線沒有顏色（看不到），一併修正。Measure Values 與另一個
  量值疊成雙軸時，另一個量值的趨勢線原本以重複的資料列配適（觀測數是兩倍、P 值不對）、顏色是灰色，也修正了
- 查證不是錯誤：預測勾「以 0 填補」後沒有預測——重現不出來；稽核當時存下的那張工作表重新查詢有預測，
  截圖右上角是「儲存中…」（存檔完成前就看了畫面）。補上「以 0 填補」的測試（原本沒有）
- ✅ 已修：dashboard 的圖片物件直接加入是壞圖——改成先在「編輯圖片物件」選圖片（電腦上的檔案或報表中已有的），
  按確定才加入；找不到圖片的區塊不顯示破圖
- ◐ 部分：刪除目前的工作表會被踢出編輯器且不能復原——刪除後留在編輯器、開啟左邊的分頁，刪除前說明不能復原；
  **復原沒有做**：編輯的歷程是每個分頁各自的定義，換分頁就重來，要能復原刪除得改成整份報表的歷程（重新設計）
- ✅ 已修：連按兩下不是目前的分頁只會切換——切過去並開始改名
- ✅ 已修：分頁很多時目前的分頁不捲進畫面——開啟、切換與新增分頁時捲到看得到的範圍
- ✅ 已修：篩選「頂部」的「依」列出 `[Calculation_…]`——改成欄位的名稱（存檔的公式不變）

還沒處理的：

- 伺服器上發布的名稱不見：首頁、檢視器與搜尋用的是報表內部的名稱，不是發布時填的名稱（已核對：`app.py`
  回的是 `ir.workbook.name`）
- 多選下拉的選單被篩選區塊裁切、點外面或按 Esc 不收（已核對：`.zone-box` 是 `overflow: hidden`，選單在區塊內）
- 一般圖表不能拖曳框選，拖曳時反白座標軸的文字
- 訂閱的 PDF 右邊約五分之一被裁掉（dashboard 比頁面寬時沒有縮放），並印出介面文字
- 其他：載入中顯示內部代號；留言與萃取更新的時間是不標示的 UTC；proxy 模式未知帳號的訊息不對；摘要 CSV 的
  數字是浮點數原樣（909369.9110000005）
- 修上面 9 項時看到、沒有處理的：畫圖的附註（render 的 `notes`，例如預測估計不出來的原因、尚未支援的畫法）
  在檢視器與編輯器都不顯示，預測算不出來時使用者看不到原因；標籤上有多個欄位（每個欄位一行）的文字表，列高
  不會跟著變高，上下列的文字會疊到；資料窗格的 Measure Values 不能連按兩下加入檢視

**與 Tableau 差最多的（桌面版）**

- 檢視、各架、標題、座標軸、標記、圖例、dashboard 區塊都沒有右鍵選單
- 「顯示篩選」「顯示參數」在編輯器裡不出現控制項，要到檢視器才看得到
- dashboard 並排的版面不能用拖的排：沒有落點預覽、邊界拖不動、區塊搬不動
- 計算欄位編輯器沒有自動完成、函式清單與著色，欄位拖不進去
- 新做的圖外觀不同：離散日期的「自動」是長條不是折線，欄標題的位置與日期的寫法不同
- 分頁列：隱藏的工作表仍顯示、不能拖曳排序、工作表一律排在 dashboard 之前
- 連按兩下座標軸或標題沒有反應；座標軸與標題沒有排序圖示；圖例不能點選醒目提示或改色
- Delete 與拖出架外不能移除膠囊；Ctrl+W 是關閉報表（Tableau 是交換欄列）
- 色彩、工具提示、標籤、格式都是按確定才套用的對話框；色盤顯示內部代號
- 開啟後先進檢視模式；只能存 .tmigx；編輯器裡沒有匯出與列印

**與 Tableau 差最多的（伺服器端）**

- 首頁不能瀏覽內容：沒有 Project、縮圖、排序、擁有者、修改時間，也沒有報表的頁面
- 沒有分享鈕；改篩選後網址不變；`?Region=West` 這類網址參數沒有作用
- 相對日期與條件篩選的控制項唯讀；欄位標題與座標軸沒有排序圖示
- 內容的擁有者沒有畫面可以改名、移動、刪除、設權限、排萃取更新，都在只有管理員進得去的站台管理
- 手機（390×844）：工具列占掉大半，dashboard 被壓到看不到圖表
- 點圖例不醒目提示、多選沒有合計、工具提示沒有檢視資料、檢視資料不依選取
- 檢視畫面上多出驗證用的「篩選組合」與每張工作表的「N 列 資料」；分頁是下拉選單
- PDF 要經瀏覽器的列印對話框，不能直接下載、不能一次匯出多張工作表
- 管理：沒有有效權限的檢視、沒有使用統計的畫面、不能匯入使用者

**兩邊都有的**：用語不一致（dashboard／儀表板、Story／故事、資料來源／資料源、Project、view）、英文與內部代號
外露（Grand Total、HTTP 狀態碼；篩選「頂部」的 `[Calculation_…]` 已修，其他地方還沒有逐一檢查）。

**沒有實測到的**：Tauri 外殼裡的原生對話框與安裝檔、列印與 PDF 的實際輸出、資料庫的 Live 連線與成功的萃取更新、
密碼與 OIDC 登入、常駐的排程器、大資料量與多人同時使用，詳見兩份原始紀錄的最後一節。

## 五、建議的順序

1. 在 Windows 上補上引擎再跑一次一鍵檢查：裝 PostgreSQL（Spark 另需 Java 17 與 `uv sync --group spark`）後設
   `TMIG_REQUIRE_ENGINES=1`。沒有引擎的部分 2026-11-16 已經跑過（第三部分的 5）；公司的電腦若不是那一台，
   也在公司的電腦上跑一次
2. 盤點 Tableau Server（第三部分的 3），挑試點的報表
3. 設定公司資料庫的連線並實測（第三部分的 1、2）
4. 移轉試點的報表、比對數字，把不一致的地方修掉
5. 試用桌面版的安裝檔（2026-11-21 已在 Windows 本機重建）：安裝、開啟報表、編輯、存檔、登入伺服器與發布
6. 依盤點中實際用到的功能補第一、二部分
